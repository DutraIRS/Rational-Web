## 1. High: anonymous requests evict every live page and session

The first GET of an interactive page creates a session (`pages.py:188`, `ctx.session.csrf`) and a
`PageRuntime` (`pages.py:207`). Both live in process-wide stores that drop the least recently used
entry when full: 5,000 pages (`app.py:109`, `app.py:184`) and 100,000 sessions (`session.py:165`).
Nothing limits how many one client creates, so a burst of anonymous requests pushes out real users.

**Reproduced** with a default `App()` and an in-process client: a user's click returns 200; after
5,000 cookie-less GETs (8 seconds, one process) the same click returns `410 This page expired`, the
page reloads and unsaved input is lost. About 100,000 requests evict every in-memory session, which
signs everyone out.

Related:

- The per-page-view event limit (`protocol.py:107`) is bypassed the same way: each new page view
  starts with a full bucket.
- With `PersistentSessionStore` or `page_snapshots`, each anonymous GET also writes a record that
  lives 24 hours (`pages.py:210`), so Redis or the SQL table grows without bound until it runs out
  of memory or evicts real sessions.
- `docs/security.rst:32` presents "bounded in number" as a protection.

**Fix:** give each session a small quota of live pages and evict that session's own oldest page
first; create the session and runtime on the first event rather than on the GET (the resume path
already rebuilds a runtime from a route); limit page creation per IP by default; keep separate
pools for signed-in and anonymous visitors.

## 2. Medium: `@remote` skips the CSRF check when the request has no framework session

`backend/services.py:136` checks the token only if `rw_sid` loaded a session. An app that signs
people in with its own cookie (an `app.authenticate` function reading
`ctx.cookies.get(..., signed=True)`) has no CSRF protection for visitors without `rw_sid`: theirs
expired after 24 hours, was evicted by finding 1, or was never created.

**Reproduced** on FastAPI 0.110, the minimum in `pyproject.toml` and the version the
`minimum-dependencies` CI job tests. A POST with only that cookie, no `X-RW-CSRF` header and no
Content-Type ran an `auth="required"` method and returned `200 {"deleted": true}`. Browsers send
such a request without a preflight (`fetch(url, {method: "POST", mode: "no-cors", credentials:
"include", body: new Blob(["{}"])})`). FastAPI 0.165 refuses a body without
`Content-Type: application/json`, and the cookie's default `SameSite=Lax` stops cross-site POSTs,
which is why this is Medium rather than High.

**Fix:** require the token whenever the principal did not come from a bearer token (or whenever the
request carries cookies); reject non-JSON bodies in the framework instead of relying on FastAPI's
default; raise the FastAPI minimum.

## 3. Medium: Stripe checkout links

- `checkout_url()` (`stripe.py:107`) signs its parameters into a link that anyone holding it can use
  for 24 hours (`stripe.py:140`). It is not bound to the visitor's session, so a link carrying
  `customer=` opens a checkout for that customer for whoever finds it in a Referer, a log or a
  shared screenshot.
- `_checkout` is a GET with side effects (`stripe.py:136`): every click, link prefetch or crawler
  visit creates a Checkout Session through the Stripe API.
- Without `base_url`, the success and cancel URLs come from `request.base_url` (`stripe.py:144`),
  that is, from the Host header. Anyone can request the link with `Host: evil.example`, take the
  Stripe URL from the 303 response and send it to a victim, who lands on evil.example after paying.
  The framework has no allowed-hosts setting to stop this.

**Fix:** create sessions on a POST with CSRF, or bind the signed value to the session id; shorten
`max_age`; require `base_url` (or check Host against a list).

## 4. Low: session ids are stored unhashed

`stores.py:352-353` uses the raw session id as the Redis/SQL key, and `resume.py:79` writes it into
every page snapshot. Whoever can read the store (a backup, SQL injection elsewhere in the app, a
shared Redis) gets live session tokens. `bots.py:113` already hashes ids for exactly this reason
("session ids stay out of the store's keys"). **Fix:** key records by SHA-256 of the id.

## 5. Low: SMTP with `security="none"` sends the password in clear text

`mail.py:137` logs in without TLS when `security="none"` and a username is set, while
`_http.py:57` refuses to send credentials over plain HTTP. **Fix:** refuse `username` together with
`security="none"`, or require an explicit opt-in.

## 6. Low: release supply chain

- `.github/workflows/release.yml:64` publishes with `pypa/gh-action-pypi-publish@release/v1`, a
  branch, in the job that holds `id-token: write`. Pin it to a commit SHA.
- `.github/` has no `dependabot.yml` and CI has no pip-audit step, so action and dependency updates
  are manual (pip-audit is clean today).

## 7. Low: the examples teach unsafe patterns

The README calls the examples "laid out like a real project", so people will copy them.

- `examples/blog/settings.py:10`: the admin password defaults to `"rational"` when `BLOG_PASSWORD`
  is unset, so a deployed copy is open to anyone who has read the repository. Refuse to start
  without it outside `--dev`.
- No sign-in handler uses `@limit` (`examples/blog/views/pages/admin.py:37`, the user-platform
  sign-in). With finding 1, password guessing is limited only by the request rate.
- `examples/social-network/services/social.py:64-70`: `suggestions(limit)` is a `@remote(GET)`
  with no cap. The other three list methods cap at 100 with an inline `min(limit, 100)`; the cap was
  copied by hand and missed here, so `?limit=100000` returns every member.
- `examples/user-platform/services/accounts.py:19-25`: "the first account becomes an administrator"
  counts and then inserts, so two sign-ups at the same moment on an empty database can both become
  admin.

## Docs that say more than the code does

- **D1.** `oauth.py:19-21`: "a nonce and a PKCE challenge, so an intercepted code is useless". The
  nonce is checked only for Apple (`oauth.py:227`). For Google, Microsoft and generic OpenID Connect
  no ID token is read, so the nonce does nothing (state and PKCE do the work). The discovery
  document's `issuer` is not compared with the configured one either (`oauth.py:94-96`).
- **D2.** `stripe.py:25`: "replayed or forged calls are rejected". Replays within the 300-second
  tolerance are accepted, since nothing de-duplicates event ids. Say that handlers must be
  idempotent.
- **D3.** `accounts.py:26` and `docs/security.rst:36`: "in the same time". For an existing account
  the call also renders the email and signs a token, so it is not constant-time. "About the same
  time" would be accurate.
- **D4.** `README.md:74` and `docs/security.rst:59`: "nonce-based CSP". The nonce applies only to
  `style-src`; `script-src` is `'self'` (`http.py:125`). That is strict (no inline script at all),
  but any same-origin file can run, such as one served from an `app.static` folder of uploads.
  Describe it as same-origin scripts plus nonced styles.
- **D5.** The README's "On the wire" table lists `runtime.js` (8.8 KiB gzipped; measured and
  accurate). Pages with client components also load `islands.js`, another 10.5 KiB gzipped. Add a
  row.

## Code quality: SOLID, KISS, DRY, PEP 8

- **Q1. Single responsibility.** `App.__init__` takes 47 keyword arguments and runs 95 statements
  (`app.py:87-258`). Besides configuration, `App` serves endpoints, compiles client modules, follows
  the bus and runs the lifespan. Group the settings into a few config objects (limits, sessions,
  client side) and move the endpoint handlers out.
- **Q2. Complexity.** `client/compiler.py` is 1,513 lines, with methods of 26 and 27 branches
  (`compiler.py:592`, `compiler.py:876`). `styling/compiler.py:133` (`_property_table`) has a
  cyclomatic complexity of 31 and `protocol.py:90` (`handle_event`) 17. In all, 16 functions exceed
  ruff's C901 limit of 10.
- **Q3. Asserts as guards.** `assert` checks runtime invariants on production paths
  (`runtime.py:141, 153, 197, 218, 361, 397`, `app.py:688, 701`, `bots.py:179, 186`). Under
  `python -O` they vanish and the failure surfaces later, less clearly. Raise explicitly.
- **Q4. Defense in depth with a gap.** In `styling/compiler.py:140`, `plain()` with a mapping returns
  the text without `_safe()`, though line 278 describes `_safe` as the defense-in-depth layer.
  Validation at construction covers strings only, so a non-`str` value (an enum, say) skips both
  checks. Apply `_safe` in both branches.
- **Q5. PEP 8.** `line-length = 120` in `pyproject.toml` is above PEP 8's 79 (or 99 by team
  agreement). Everything else ruff checks under the project's rules passes.
